# agent-office v0.1.0

The first release (2026-11-08). agent-office runs a team of AI coding agents (Claude Code) on a git
repository. Each worker runs in its own rootless Podman sandbox, without the API credential and
without network beyond an allowlist. A local web UI shows the task board, live terminals, costs
and a pixel-art office. It is pre-1.0: flags, the HTTP API and the database schema may still change
(migrations are forward-only and back up the database first).

## Highlights

- **Team workflow:** an optional Architect agrees a plan with you (approved in the UI and committed
  as a spec), a Tech Lead assigns sub-tasks in dependency order, workers implement them, QA merges
  and tests the branches and gates the goal, and an Assistant briefs you. Roles are YAML; a model
  per role.
- **Isolation:** rootless Podman per worker with `--network none`; egress only through a per-agent
  CONNECT allowlist; the API credential injected by the daemon's proxy; work handed back as a
  verified git bundle; full permissions only inside the container. Worker images are built from a
  pinned Debian snapshot.
- **Coordination:** a team MCP server per agent socket (`create_task`, `assign_task`,
  `report_done`, `send_message`, `request_access`, …), authorized from the caller's role. Messages
  are claimed once in SQLite and delivered when the recipient's turn ends; access requests wait for
  your approval.
- **Guardrails:** dependency and file-ownership checks on assignment, `git merge-tree` conflict
  checks on report, budgets refused at the API socket. Pushes are flagged until you accept unusual
  commits (identity, `.github/` changes, issue-closing keywords). Merging is always yours.
- **GitHub loop (opt-in):** finished work becomes a pull request, which an internal reviewer agent
  or CodeRabbit reviews. Feedback relaunches the original worker.
- **UI:** a task board, live xterm.js terminals with copy and paste, an inbox, the Office view
  (PixiJS), and a Usage tab with tokens and estimated cost per goal, task, agent, session and model.
  Session history and resume after a restart. An installable PWA for your phone over
  `tailscale serve`, with paired devices.
- **Stack packs:** the built-in `go` and `node` packs, or your own YAML, choose the worker image,
  egress hosts, secrets, skills and MCP servers.

## Install

Linux, amd64. You need rootless Podman and Claude Code (logged in); Go and Node are only needed to
build from source.

```sh
sha256sum -c SHA256SUMS
tar xzf agent-office_v0.1.0_linux_amd64.tar.gz
cd agent-office_v0.1.0_linux_amd64
./agent-office version                     # v0.1.0
```

Then follow the README's quick start from the token step on: store a `claude setup-token` token in
`~/.config/agent-office/oauth-token` (mode 0600, directory 0700), build a worker image
(`./agent-office worker-image --pack go`), run `./agent-office serve --repo <repo>`, and pair your
browser with `./agent-office pair`.

## What is in the archive

`agent-office` (a static binary with the web UI and the worker image's build files embedded),
`LICENSE` (MIT), `README.md` and these notes. Built by `make release` from a fresh worktree of the
`v0.1.0` tag with Go 1.27.3 and Node 26.13.0. The tarball is deterministic (fixed file order, owner
and timestamps), so rebuilding the tag with the same toolchain gives the same checksum.

## Known limitations

- Linux only, amd64 only. Claude Code is the only agent CLI so far.
- One user, and one goal with one Tech Lead, Architect, QA and Assistant at a time.
- Follow-up and conflict rounds do not survive a daemon restart, and their relaunches start fresh
  sessions.
- No push notifications on the phone; a QR code for pairing is not there yet.
- The binary is not signed; the checksum detects corruption, not a malicious upload.
- Sandboxed agents' security depends on rootless Podman and the host kernel. The threat model, with
  its residual risks, is in `docs/architecture.md`.
